# Crochet — интерактивная игра о вязании

**Игра в браузере:** https://alexaxel.github.io/crochet/

Физический XPBD-прототип **воздушной петли**, не обучающий сайт и не иллюстрация схем. Весь экран — деревянный стол. На нём лежат клубок, маркеры, две запасные спицы; **работает один крючок**, поскольку воздушная петля при вязании крючком выполняется одним крючком. Все предметы генерируются кодом, ассеты художника пока не требуются.

## Управление

- **1** — выполнить воздушную петлю. Крючок захватывает участок рабочей нити и тянет новый сгиб через старую рабочую петлю.
- **2** или **Backspace** — распустить последнюю петлю. Во время анимации отменяет текущую операцию.
- **R** — начать цепочку с самого начала.
- **Space** зарезервирован под переход к новому ряду, **пока недоступен**.
- Мышь — вращение и масштаб для просмотра пересечений под разными углами.
- Кнопка шестерёнки — цвет пряжи, темп анимации, звук, подсветка рабочей петли и клавиши.

Выполняется **только одна техника: воздушная петля**. Никаких имитаций СБН, прибавок и носков в текущей игровой сцене нет.

## Как устроена физика в Alpha 0.4

**Самостоятельный физический модуль:** src/core/yarnPhysics.ts. В отличие от прежней альфы, после нажатия **не строится геометрический шаблон воздушной петли**.

1. В качестве начального состояния есть один заранее завязанный скользящий узел, как при настоящем начале вязания. Это единственная исходная форма: новых заранее нарисованных петель нет.
2. Пряжа — одна цепочка постоянных материальных точек, а не сцепленные картинки. Координаты и предыдущие координаты каждой частицы переживают несколько операций.
3. Система XPBD фиксированными подшагами решает близкую к нерастяжимой длину соседних участков, приближённый изгиб, столкновения несоседних участков нити, контакт с поверхностью стола, затухание и временную опору старой петли.
4. При нажатии контроллер **захватывает существующую материальную точку** рабочей нити и перемещает захват за петлю, сквозь её отверстие и наружу. Остальная нить должна двигаться вследствие физических ограничений. Крючок визуально прикреплён к физическому захвату.
5. Из клубка выдаётся дополнительная длина материальной нити с укладкой её первоначально внутри клубка, вместо бесконечного растяжения существующих сегментов.
6. Когда протягивание закончено, захваченный участок становится новой активной петлёй. Фиксируется снимок физического состояния для обратимой отмены; затем уже существующие узлы продолжают кратковременно расслабляться.

Визуализация использует Three.js, отображает текущее положение физических сегментов и сохраняет вид сверху/2,5D. **PixiJS не является физическим движком; добавление его сейчас не улучшит динамику нити.**

Файлы:
- src/core/yarnPhysics.ts — XPBD-частицы, ограничения, столкновения, захват и подача нити.
- src/render/ChainTable.ts — тонкая трубка по фактическим координатам физических частиц, крючок, окружение.
- src/main.ts — игровые клавиши и скрытые настройки.
- tests/yarnPhysics.test.ts — тесты физического состояния, длины, 3D-пересечения, подачи и распускания.

## Исправление физического захвата — Alpha 0.4.1

При сравнении с живым вязанием обнаружились два нарушения причинно-следственной связи:

1. В старом коде рабочая головка крючка была отделена от «захваченной» физической точки пряжи по Z на 0,18 единицы; нить перемещалась принудительно даже **до захвата**.
2. После первого звена активная петля провисала практически на стол, и следующий захват не мог корректно протянуть нить **сквозь её отверстие**.

Теперь движение разделено на физические состояния: (a) свободный крючок подходит к текущему положению пряжи; (b) захватывает **конкретную материальную точку**, и с этого момента головка крючка и пряжа имеют один контакт; (c) крючок вытягивает этот участок сквозь открытую, поддерживаемую петлю; (d) старая петля остаётся в цепочке, а захваченная становится новой активной петлёй. Крючок удерживает её над поверхностью стола. Из-за этого каждое следующее действие использует **реальное состояние той же физической нити**, а не возвращается к заранее нарисованной кривой.

Физический расчёт отклоняет завершение операции, если не было захвата и прохождения участка нити с задней стороны отверстия на переднюю. Тесты проверяют это, включая два последовательных звена, перемещение соседних физических частиц и откат, а также корректную реакцию на точные пересечения сегментов.

**Не доказано:** отсутствие всех самопересечений при большом количестве петель (пока отсутствует CCD), правильная тонкая геометрия захвата и натяжение при разных материалах. Симуляцию по-прежнему нужно сравнить с реальным видео эксперта; отсутствие ошибки в математическом тесте не является доказательством, что физическая воздушная петля выглядит абсолютно правильно.

## Что ЕЩЁ не решено

Физический расчёт **есть и выполняется на каждом подшаге**, но это **не готовый научно проверенный симулятор вязания**. Кинематический контроллер задаёт траекторию крючка; он ещё не рассчитывается через детальный контакт крючка со всеми нитями. Изгиб — упрощённое ограничение, а не полноценная модель упругого стержня с кручением. Крупное переплетение иногда может пересечь другое между подшагами: пока нет полноценной непрерывной проверки столкновений и математической гарантии сохранения топологии. Трение не откалибровано по реальным материалам. Подача из клубка упрощена. Отмена операции использует снимок состояния, а не симуляцию обратного вытягивания.

Поэтому эксперт должен оценивать **сначала одну настоящую воздушную петлю**, затем две-три последовательные. Пока геометрия не подтверждена, увеличение словаря техник не имеет практического смысла. Если петля выполняется неверно, исправляем физический контроллер/контакты — не подрисовываем красивую картинку. На этой стадии для производительности ограничиваем рабочую цепочку несколькими ВП.

Старые src/core/chainMechanics.ts, src/core/model.ts, src/core/geometry.ts, src/render/YarnScene.ts и src/learn/lesson.ts лежат в репозитории как эксперименты, **но в игровом экране не используются**.

## Разработка

    npm install
    npm test
    npm run dev
    npm run build

После изменения main GitHub Actions автоматически запускает build:pages и помещает готовые файлы в main/docs; затем GitHub Pages публикует сайт.

Последовательность следующих этапов после экспертного принятия воздушной петли: надёжная топология цепочки → моделирование реальных операций СБН через то же ядро → выбор способа ввода крючка → схемы и изделия → художественная полировка и Unity.
